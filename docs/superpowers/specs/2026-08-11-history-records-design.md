# 最近记录与历史记录页设计

## 目标

首页“最近记录”在桌面端不超过左侧体重趋势卡片高度，并在有限空间内尽量多展示身体、训练和睡眠记录。新增只读 `/history` 页面，作为首页最近记录的完整延伸，统一查看和筛选全部历史数据。

## 首页最近记录

- 保持现有左右两栏结构，桌面端右侧卡片高度跟随左侧体重趋势卡片
- 记录区域使用固定可用高度和 `overflow-hidden`，超出内容直接隐藏，不显示内部滚动条
- 单条记录采用紧凑布局：标题、类型标签和时间尽量同行，缩小上下间距与指标标签尺寸
- 身体记录展示全部原始指标，并在有数据时补充 BMI、腰臀比
- 训练记录展示训练类型、持续时长和备注
- 睡眠记录展示睡眠时长、睡眠分数、就寝时间和起床时间
- 备注或说明最多显示一行，超长内容截断
- 卡片底部增加轻量渐隐区域与“查看历史记录”入口，明确还有更多内容
- 移动端不强制与图表等高，但仍使用紧凑布局，避免卡片过长

## 历史记录页

- 新增 `/history` 路由，页面标题为“历史记录”
- 页面仅用于查看，不提供编辑、删除或新增入口
- 身体、训练、睡眠记录合并为一条按时间倒序排列的统一时间线
- 支持记录类型筛选：全部、身体、训练、睡眠
- 支持开始日期和结束日期筛选，沿用现有 `AppDateField`
- 完整展示每条记录的指标、时间和说明，不进行首页式高度裁切
- 无结果时显示与当前筛选条件一致的空状态
- 首页“查看历史记录”跳转到 `/history`

## 组件与数据边界

- 抽取统一记录展示模型，负责把身体、训练和睡眠数据转换为一致字段：唯一键、记录类型、发生时间、标题、指标列表、说明
- 抽取可复用记录列表组件，通过 `compact` 属性区分首页紧凑模式和历史页完整模式
- 首页只负责限制容器高度和提供跳转入口
- 历史页只负责筛选条件和传递完整记录列表
- 继续使用现有 `useTrackFitData` 数据源，不修改 v6 JSON 结构

## 响应式规则

- `xl` 及以上：左右两张卡片等高，最近记录内容超出后隐藏
- `xl` 以下：恢复自然高度，避免手机端因固定高度丢失主要内容
- 历史页在桌面端使用清晰的筛选栏和列表，在移动端筛选项纵向排列

## 测试与验收

- 单元测试覆盖三类记录合并、时间倒序和类型/日期筛选
- 端到端测试覆盖首页存在“查看历史记录”入口并可进入 `/history`
- 端到端测试覆盖历史页仅查看、筛选控件存在且无编辑删除按钮
- 类型检查、涉及文件 Lint、单元测试和相关端到端测试均通过
- 桌面端人工检查右侧卡片不超过左侧图表卡片高度；移动端检查无内部滚动和内容溢出

## 非目标

- 不在历史页增加编辑、删除、新增能力
- 不改变身体、训练、睡眠的持久化结构
- 不使用 `ResizeObserver` 动态计算记录条数
- 不在首页最近记录区域增加内部滚动条
